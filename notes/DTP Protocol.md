DTP (Dynamic Trunking Protocol) is a Data Link Layer (Layer 2) protocol designed by Cisco.Its building purpose is to avoid configuring every port to trunk.Cisco developed this protocol to establish 802.1Q trunk link between switches or routers automatically.It basically sends the DTP frame through all ports that's state is configured to `dynamic auto` or `dynamic desirable` and waits for the reply.Normally, end devices ignores the DTP frames completely because it doesn't run the Cisco DTP stack, which leaves the switchport as an Access Port.
However, if your computer crafts and sends a reply DTP frame it can establish a 802.1Q trunk link between devices and that's where adversaries can perform different types of attacks ,such as [[VLAN Hopping]].
### Here is the detailed view of the DTP frame:
```
1. Frame 271: Packet, 60 bytes on wire (480 bits), 60 bytes captured (480 bits) on interface -, id 0
2. IEEE 802.3 Ethernet 
3. Logical-Link Control
4. Dynamic Trunk Protocol: CISCO-vIOS (Operating/Administrative): Access/Desirable (0x03) (Operating/Administrative): ISL/Negotiated (0x40): 0c:7c:bd:44:00:00

```

```
        .... ...1 .... .... .... .... = IG bit: Group address (multicast/broadcast)
    Source: 0c:7c:bd:44:00:00 (0c:7c:bd:44:00:00)

    Length: 44

```
-  **IEEE 802.3 Ethernet** :  specifies the framing standard being used. Nowadays, it is not used commonly.Modern computers use Ethernet II framing standard.
-  **Src: 0c:7c:bd:44:00:00** : The Source MAC address
- **Destination: CDP/VTP/DTP/PAgP/UDLD (01:00:0c:cc:cc:cc)** :  The Destination MAC address.The MAC address (01:00:0c:cc:cc:cc) represents the Cisco's proprietary multicast address.Any Cisco device  receives this frame will process it because it handles the multiple Cisco-specific protocols  ,such as **Cisco Discovery Protocol**, **VLAN Trunking Protocol**, **Dynamic Trunking Protocol**, **Port Aggregation Protocol**, and **UniDirectional Link Detection**.

```
Logical-Link Control
    DSAP: SNAP (0xaa)
        1010 101. = SAP: SNAP
        .... ...0 = IG Bit: Individual
    SSAP: SNAP (0xaa)
        1010 101. = SAP: SNAP
        .... ...0 = CR Bit: Command
    Control field: U, func=UI (0x03)
        0. 00.. = Command: Unnumbered Information (0x00)
        .... ..11 = Frame type: Unnumbered frame (0x3)
    Organization Code: 00:00:0c (Cisco Systems, Inc)
    PID: DTP (0x2004)
```

- **DSAP (Destination Service Access Protocol) :** This tells the destination device which protocol stack inside the OS should handle this packet.And the 0xaa inside the SNAP(Subnetwork Access Protocol) indicates that this is proprietary protocol.
- **SSAP (Source Service Access Protocol) :** Shows the protocol service that sent the packet. Like DSAP, it also points to **SNAP (0xaa)** .
- **Control Field :**  defines the type of LLC transmission.**U** means Unnumbered Frame, which is used for sending frames without receiving an acknowledgement (similar to UDP at Layer 4).
- **UI (Unnumbered Information) :** shows that it is just carrying data payloads without establishing any formal session or tracking sequence numbers.
- **SNAP(Subnetwork Access Protocol) :**  Because IEEE 802.2 LLC doesn't know about modern protocols , it uses SNAP as an extension mechanism to identify specific manufacturers and their proprietary protocols.Inside SNAP , **Organization Code** is a specific code used for identifying the manufacturer and **PID** (Protocol Identifier) assigns the specific protocol belonging to that manufacturer.
